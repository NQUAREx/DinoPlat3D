# Dino Run development rules

## Context/tool economy and subagent orchestration

- Read instructions once per task; search with scoped rg and bounded output. Exclude dependencies, generated assets and historical logs unless relevant; batch independent reads and summarize large results.
- Keep one authoritative location per fact. Update current rules in place; avoid duplicate history and repeated validation narratives. Run relevant checks once per revision; repeat only for changes or unresolved failures.
- Delegate only independent, bounded work with explicit file ownership, constraints and expected evidence. Share minimal context; avoid duplicate investigation and overlapping edits. The main agent integrates results and owns final verification.
- Player-visible Russian/English names must use neutral physical, nature or technology terms; avoid magic, occult and mythical-character names. Preserve inventory IDs when renaming; ordinary mineral and astronomical terms are allowed. Technical tool names and attribution remain accurate.

## Scope, platform and licence

- Work only in NQUAREx/DinoPlat3d. Never modify/publish the separate live original NQUAREx/dinoplat.github.io.
- Static Three.js 0.186.1 + TypeScript + Vite client for GitHub Pages, with the owner-requested Supabase backend for profiles, rankings and analytics. No physics/particle engine or unnecessary runtime dependency. npm run dev / build / preview must keep working.
- Owner approved GPL-3.0-only. Preserve LICENSE, public licence/source links and original imported VOX archives/attribution: hushenghao/dino3d commit cae7ed3da5646839e6aaa24f698b8c07cc3ffc85, ©2020 Abraham Tugalov. Never copy upstream gameplay code. Imported dinosaur/cactus VOX files are archival only, never runtime assets or model-builder inputs.
- Use local geometry/animation skills when applicable. I/O/model loading/authoring is async and parallel where useful. Fixed-step simulation, gesture state and RAF rendering remain synchronous: no promises/microtasks in hot loops.

## Terrain

- No floor atlas/textures or500m biome timer. Desert-majority LandscapeField thins oasis/lava patch candidates to one-third with independent seeded salt205, preserving footprint shape/size. Tall macro mountains occur in32% of320m cells (half previous64%). All positive elevation is divided by3 with42m cap; negative relief remains down to-16.6m. Medium hills and opening foothill remain. Summit islands are independently thinned. Both ravine families and14m pit depth remain.
- No mini-cliffs, rocky shelves, ledge generation APIs or terrain damage checks. All supported ground is traversable. Small rock/log props remain harmless walk-over supports. Fully fallen cacti/trees (motion2 or horizontal lean) are scenery with no damage; partial falls can still collide.
- Ground is224m/56² cells at4m, four persistent mesh banks: ground/bed/walls, water, lava, closed wooden bridge decks. Shared lattice vertices jitter radially <.85m; signed hazard/bridge masks clip each triangle into non-square polygons. CPU height/support must use those same warped triangles and interpolated masks. Bridge planks follow crossing direction, never hard-code worldZ. Avatar, collision, pickups, dust, shadow and camera use absolute ground elevation; jumps preserve absolute airborne momentum across slopes.
- Four terrain banks retain fixed12,343,296-byte CPU/GPU geometry buffers plus158,496bytes CPU scratch. Four Lambert materials; no identity indices, rebuild allocations or growing cache. Rebuild only on anchor/seed/revision/enabled changes. Bridge grain is stable at million-metre coordinates. Independent pit clipping and zero-area fragment rejection must prevent liquid wedges and doubled walls. Gray pit haze is one byte per vertex mixed in the existing ground shader.
- Rivers/ponds/lava/ravines/pits have visible beds/walls and are fatal when fallen into regardless of immunity. Bridges reserve traversable crossings, not invisible walkable water. Bird/tumbleweed numerical states and falling-obstacle pivots live in the fixed world pool, with reaction-time telegraph/cooldown. Dynamic colliders track poses; don't spawn render objects outside visibility. Scenery uses a bounded deterministic cache and instanced banks, no per-prop scene objects.
- Dry pits/ravines NEVER receive bridge decks, even inside a positive bridge mask. CPU classification and renderer must both enforce this. Relocate whole pit footprints away from reserved safe corridors; never cut/fill artificial land causeways through holes or silently delete pit families. Both pit families remain independently populated. Bridges are only over water/lava; dry holes require a jump or detour.
- Pit rendering clips an independent interpolated pit mask inside the combined hazard polygon. Pit beds/walls are14m deep with no liquid bank; water/lava keeps4.8m beds. Never classify a whole clipped triangle from its centroid or liquid wedges reappear.
- Camera FOV widens by up to12° on ascents/descents with the eased terrain probe; it does not change surface speed. Every generated tumbleweed starts moving at7.5m/s in a seeded direction immediately, without a launch gate or visible lifetime expiration. Only far-outside-view tumbleweed retires.
- Falling cactus/tree eligibility remains32% (DEV0..60%); full horizontal falls become harmless decoration. Pit rims use4096 bounded decorative stone slots within5696 total scenery entries and13 fixed instanced banks; seeded size/yaw/scatter, dry-footprint checks and camera culling. Stones never add damaging colliders.
